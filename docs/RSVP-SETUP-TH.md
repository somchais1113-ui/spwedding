# เปิดรับคำตอบเข้าร่วมงาน — Google Sheets

ไฟล์เว็บฉบับนี้มีฟอร์มและโค้ดเชื่อมต่อแล้ว แต่ยังไม่ได้เปิดใช้ระบบรับคำตอบบน Google/Vercel จริง การติดตั้ง Google Drive ในแชตช่วยให้จัดการชีตได้ แต่ไม่ได้มอบสิทธิ์ให้เว็บไซต์ของแขกเขียนข้อมูลเอง ต้องเปิดใช้ตัวรับข้อมูลตามขั้นตอนนี้ด้วย

ชีตปลายทาง: https://docs.google.com/spreadsheets/d/1He7PKjI5SvLfFaqupgbHIghvl7S2nM_QUg6JWdzztt0/edit

เมื่อเปิดใช้แล้ว คำตอบอยู่ในแท็บ **RSVP** ประกอบด้วย รหัสคำตอบ / บันทึกครั้งแรก / อัปเดตล่าสุด / ชื่อผู้ตอบ / สถานะการเข้าร่วม / จำนวนผู้ร่วมงาน
จำนวนรวมตัวผู้ตอบด้วย หากเลือก 6+ ต้องระบุจำนวนจริง หากไม่สะดวกมา จำนวนเป็น 0

## 1. ตั้งค่าตัวรับข้อมูลในบัญชี Google ของเจ้าของชีต

1. เปิดชีตด้านบน เลือก Extensions → Apps Script
2. วางเนื้อหาจาก `integrations/google-sheets/Code.gs` ลงในโปรเจกต์สคริปต์ใหม่ของงานนี้ หากมีสคริปต์เดิมอยู่ อย่าทับโค้ดเดิม ให้ใช้โปรเจกต์ใหม่ที่ script.google.com แล้ววางโค้ดนี้แทน
3. ใน Project Settings ตั้งเขตเวลา Asia/Bangkok; ไฟล์ `appsscript.json` ที่แนบเป็นค่าตั้งต้นหากใช้โปรเจกต์ใหม่
4. เพิ่ม Script property ชื่อ `RSVP_SHARED_SECRET` ค่าเป็นข้อความสุ่มอย่างน้อย 32 ตัวอักษร เก็บค่านี้เป็นความลับ ใช้ค่าเดียวกันกับฝั่ง Vercel ในข้อถัดไป อย่าใส่ลงชีตหรือไฟล์ `js/config.js` และไม่ต้องส่งรหัสนี้ในแชต
5. รัน `setupRsvp` แล้วอนุญาตสิทธิ์ Google สคริปต์จะสร้างแท็บ RSVP หากยังไม่มี ไม่ลบหรือแก้แท็บอื่น หากแท็บ RSVP เดิมมีหัวคอลัมน์ไม่ตรง ระบบจะหยุดเพื่อรักษาข้อมูลเดิม
6. Deploy → New deployment → Web app → Execute as: Me → Who has access: Anyone แล้วคัดลอก URL ที่ลงท้าย `/exec` (ไม่ใช้ `/dev`) ผู้เยี่ยมชมส่งผ่านเซิร์ฟเวอร์ที่แนบรหัสลับ ไม่ต้องลงชื่อเข้า Google และไม่มี API เปิดอ่านรายชื่อ
7. หากองค์กรปิดการ deploy แบบ Anyone ต้องให้ผู้ดูแลบัญชีเปิดสิทธิ์ที่เหมาะสมก่อน ไม่เปลี่ยนสิทธิ์ชีตเป็นสาธารณะเพื่อแก้ปัญหานี้

## 2. เปิดใช้บน Vercel ของเว็บไซต์เดิม

1. ใช้โฟลเดอร์ `SP-Wedding-Website` ทั้งโฟลเดอร์เป็น Project Root รวม `api/`, `lib/`, `tools/`, `vercel.json` ด้วย การอัปโหลดเฉพาะ index.html จะยังรับคำตอบไม่ได้
2. ใน Project Settings → Environment Variables เพิ่มสองค่า: `RSVP_SCRIPT_URL` = URL `/exec` จาก Google และ `RSVP_SHARED_SECRET` = ค่าเดียวกับ Script property ข้างต้น กำหนดให้ environment ที่ต้องการใช้งาน
3. ใช้การตั้งค่าใน vercel.json: Build Command `node tools/build-web.cjs`, Output Directory `public`, Framework Other แล้ว deploy/redeploy เว็บเดิม
4. ทดสอบผ่าน HTTPS จริงด้วยชื่อที่ระบุชัดว่าเป็นรายการทดสอบ ยืนยันว่าแถวใน RSVP ปรากฏก่อนเปิดรับแขก ทดสอบ 1 คน, 6+ (เช่น 8 คน), ไม่สะดวกมา, แก้ไขคำตอบ, กดซ้ำ/เน็ตหลุด จากนั้นลบเฉพาะแถวทดสอบที่สร้างเอง

Build คัดลอกเฉพาะ index.html/css/js/assets ไป public จึงไม่เผยแพร่โค้ดเซิร์ฟเวอร์และเอกสารตั้งค่า
ฝั่ง Node ทางเลือก: ตั้ง environment สองค่าเดียวกัน แล้วรัน `node server.mjs` บนโฮสต์ที่รองรับ Node 20+; guestbook เดิมยังคงทำงานตาม docs/GUESTBOOK-TH.md

## พฤติกรรมและขอบเขต

- ขึ้น “บันทึกแล้ว” เฉพาะหลัง Google เขียนข้อมูลสำเร็จ ไม่มีการใช้ `fetch` แบบ `no-cors` แล้วแสดงผลสำเร็จโดยตรวจไม่ได้
- ป้องกันการส่งซ้ำด้วยรหัสต่อเบราว์เซอร์และล็อกการเขียนใน Apps Script การแก้ไขคำตอบบนเบราว์เซอร์เดิมอัปเดตแถวเดิม การส่งจากอีกเครื่องหรือหลังล้างข้อมูลเบราว์เซอร์อาจเป็นแถวใหม่ ไม่ใช้ชื่อเป็นตัวตัดสินว่าคนเดียวกัน
- localStorage เก็บเฉพาะรหัสคำตอบ ไม่เก็บรายชื่อแขกทั้งหมด เมื่อกลับมาใหม่ฟอร์มไม่ดึงชื่อเดิมจากชีตเพื่อไม่เปิดเผยข้อมูลผ่าน endpoint สาธารณะ
- เครื่องที่ใช้ร่วมกัน: คำตอบใหม่บนเบราว์เซอร์เดิมถือเป็นการแก้ไขคำตอบของกลุ่มเดิม หากให้คนละกลุ่มตอบ ควรใช้เบราว์เซอร์/อุปกรณ์แยกกัน
- มีตรวจข้อมูล จำกัดขนาดคำขอ ฟิลด์ดักบอต และจำกัดการส่งต่อหนึ่ง instance เบื้องต้น หากเปิดรับทราฟฟิกมากควรตั้ง rate limit ที่ Vercel Firewall เพิ่ม การจำกัดในหน่วยความจำไม่ใช่ตัวนับรวมทุก instance
- ภาพตัวอย่าง HTML แบบไฟล์เดียวใช้ดูหน้าตาฟอร์มได้ การส่งต้องผ่านเว็บที่มี `/api/rsvp` พร้อมใช้งาน
- การยืนยัน RSVP กับระบบส่งคำอวยพรเป็นคนละระบบ RSVP เท่านั้นที่ส่งเข้าชีตนี้
