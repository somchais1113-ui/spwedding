# Somchai & Phantira — Navy Wedding Edition 2.4.1

เว็บไซต์งานแต่ง 25 ตุลาคม 2569 (2026) โทน Navy Blue–ฟ้าอ่อน–ขาว ใช้โลโก้หลักที่เจ้าของงานส่งมา พร้อมหน้าเปิดเว็บ Animation นับถอยหลัง และคำอวยพรแบบพิมพ์/ลายมือ

## เปิดใช้งาน

1. แตก ZIP ทั้งโฟลเดอร์ แล้วเปิด `index.html` เพื่อดูเว็บ ภาพท่องเที่ยวออนไลน์ แผนที่ และการส่งคำอวยพรต้องเชื่อมอินเทอร์เน็ต
2. แก้ข้อมูลใน `js/config.js` และตกแต่งใน `css/`
3. `SP-Wedding-Preview.html` ที่ส่งแยกเป็นตัวอย่างรวมภาพ/ฟอนต์ไว้ในไฟล์เดียว การแก้แพ็กเกจจะไม่แก้ตัวอย่างนั้นอัตโนมัติ

## สิ่งที่เพิ่ม

- หน้าเปิดงานเต็มหน้าจอ ใช้โลโก้ PNG โปร่งใสต้นฉบับ วันจัดงาน และปุ่มเข้าสู่หน้าหลัก
- แสงเคลื่อนช้า โลโก้ค่อย ๆ ปรากฏ ปุ่มมีแสงไล้ และ transition เข้าเว็บ
- ปุ่มพักภาพทั้งหน้าเปิดและหน้าหลัก รองรับ reduced motion ของอุปกรณ์
- นับถอยหลังทั้งสองหน้า โดยใช้เวลาไทย และไม่แสดงค่าติดลบหลังวันงาน
- เปลี่ยนธีมส่วนติดต่อทั้งหมดเป็น navy / ice blue; ภาพสีน้ำใช้สีธรรมชาติของต้นฉบับ เอาฟิลเตอร์ย้อมสีฟ้าออกแล้ว
- คำอวยพรแบบพิมพ์หรือ canvas ลายมือ ใช้นิ้ว เมาส์ หรือปากกา ปรับความหนา ย้อนเส้น และล้างลายมือได้
- เก็บร่างทั้งสองโหมดในอุปกรณ์เดียวกัน โดยปุ่มหลักส่งถึงเซิร์ฟเวอร์
- แนบ `server.mjs` สำหรับรับคำอวยพรส่วนกลางแบบข้อความและภาพ เมื่อเปิดใช้เซิร์ฟเวอร์
- ฟังก์ชันเดิม: คำเชิญระบุชื่อแขกด้วย `?to=ชื่อแขก`, เปิดการ์ด, ส่งความยินดี, แชร์ลิงก์, ข้อมูลสถานที่และปฏิทิน

## วันและเวลา

`date.eventDay` ตั้งเป็น `2026-10-25` แล้ว ใช้ ค.ศ. ในข้อมูลและแสดง พ.ศ. บนเว็บ

ตั้งเวลาเริ่มร่าง `2026-10-25T09:09:00+07:00` และสิ้นสุด `2026-10-25T12:00:00+07:00` ตามที่เจ้าของงานขอแล้ว นับถอยหลังถึง 09:09 น. และปฏิทินบันทึกช่วง 09:09–12:00 น. ตามเวลาไทย รายละเอียด 8 ช่วงกิจกรรมอยู่ใน `js/config.js` และ `docs/SCHEDULE-DRAFT-TH.md` ข้อความหน้าเว็บใช้ “กำหนดพิธีการ รายละเอียดดังต่อไปนี้” และจัดช่วงให้จบเที่ยงตามบริบทเดิม

## ข้อมูลที่ยังต้องเติม

- กำหนดการล่าสุดเริ่มใส่บาตร 06:00 น. แห่ขันหมาก 08:30 น. บายศรีสู่ขวัญ 09:09 น. จบงาน 12:00 น.
- ที่อยู่บ้านแบบข้อความใน `venue.address`; ใส่ลิงก์หมุดที่เจ้าของงานส่งใน `venue.mapUrl` แล้ว
- เวลาแต่ละกิจกรรม ที่จอดรถ ผู้ติดต่อ
- URL เว็บไซต์จริง `siteUrl` เมื่อโฮสต์แล้ว

## คำอวยพรสองรูปแบบการใช้งาน

### เปิด HTML / โฮสต์ static

พิมพ์หรือเขียนลายมือเพื่อดูตัวอย่างได้ ปุ่มเป็น “ส่งคำอวยพร” ไม่ใช่บันทึกในเครื่อง และไม่มีปุ่มดาวน์โหลดการ์ดในหน้าเว็บ หากเปิด file:// จะแจ้งว่ายังส่งไม่ได้ หากโฮสต์ static ไม่มี API จะแจ้งว่าส่งไม่สำเร็จ ไม่จำลองการส่งสำเร็จ

### รับคำอวยพรถึงบ่าวสาวจริง

ติดตั้ง Node.js 20 ขึ้นไป เปิด terminal ในโฟลเดอร์แพ็กเกจ แล้วรัน:

```bash
node server.mjs
```

เปิด `http://127.0.0.1:8080` ในเครื่องนั้น เซิร์ฟเวอร์แจ้งความพร้อมผ่าน `/api/guestbook-status` แล้วหน้าเว็บจะเปลี่ยนปุ่มเป็น “ส่งคำอวยพรให้บ่าวสาว” โดยอัตโนมัติ ข้อมูลถูกเก็บเป็นไฟล์ JSON แยกรายการใน `private-wishes/` แบบไม่เปิดต่อสาธารณะ ภาพลายมืออยู่ใน field `image` เป็น PNG data URL

สำหรับแขกเข้าผ่านอินเทอร์เน็ต ต้องโฮสต์ Node server หลัง HTTPS โดยกำหนด `HOST=0.0.0.0`, `PORT` ตามโฮสต์ และ `WISHES_DATA_DIR` ให้ชี้ดิสก์ถาวร สำรองโฟลเดอร์ข้อมูล อย่าใช้ filesystem ชั่วคราวของ serverless เพื่อเก็บคำอวยพร คู่มือเพิ่มเติมใน `docs/GUESTBOOK-TH.md`

**แพ็กเกจนี้ยังไม่ได้เผยแพร่ออนไลน์** การนำเฉพาะ HTML ไปวาง Vercel/static hosting จะใช้โหมดบันทึกในเครื่อง ต้องเชื่อมฐานข้อมูลหรือใช้ Node hosting ที่มีดิสก์ถาวรเพื่อรับคำอวยพรส่วนกลาง

## การตรวจสอบรอบนี้

ผ่านการตรวจ syntax JavaScript, ไฟล์ภาพ/ฟอนต์และ anchor, เวลาไทยที่ขอบเขต 09:09 น., ปฏิทิน 09:09–12:00 น., ลิงก์ Maps ตรงกับผู้ใช้, ตารางต่อเนื่อง 8 ช่วง และภาพต้นฉบับไม่มีการเปลี่ยน bytes; ระบบคำอวยพรผ่านการตรวจจากฉบับก่อนและไม่ได้แก้ในรอบนี้ ตรวจ CRC และการแตก ZIP พร้อมเปรียบเทียบไฟล์ครบแล้ว ไม่ได้ทดสอบหน้าจอและการลากนิ้วผ่านเบราว์เซอร์ในรอบนี้

อัปเดต 1.4: ใช้ภาพ JPEG ที่ผู้ใช้ส่งมาทั้งสองภาพโดยคงไฟล์ต้นฉบับ ไม่ย้อมสีหรือครอป ปรับสัดส่วนแสดงผลตามภาพจริง เอาตัวอักษรสัญลักษณ์หัวใจและลูกศรออก ปุ่มแสดงความยินดีใช้ข้อความ ไม่มีอีโมจิหรืออนุภาคหัวใจ

อัปเดต 1.5: หน้าเปิดใช้แอนิเมชัน SP ปรากฏก่อน ค่อย ๆ เผยกิ่งและดอกไม้ ตามด้วยชื่อบ่าวสาว รายละเอียดเวลาและวิธีปรับอยู่ใน `docs/MOTION-GUIDE-TH.md`


## อัปเดต 1.6 — การ์ดเปิดปกและส่งคำอวยพร

การ์ดปก Navy ใช้โลโก้สีขาวด้วย CSS display filter เมื่อแตะจะเปิด dialog และปกหมุนเปิดรอบสันซ้าย เผยข้อความบนกระดาษสีขาวมี grain texture ไม่มี hover เอียงยกการ์ด ปุ่มปิด/ESC ใช้ได้ตลอด reduced motion ข้ามการเปิดปกและแสดงข้อความทันที

ปุ่ม “ส่งคำอวยพร” POST ไปยัง /api/wishes รอผล saved:true ก่อนแสดงข้อความขอบคุณและกระดาษโปรยแบบเรขาคณิต ไม่มีอีโมจิ ขณะส่งมีวงแหวนหมุนและแสงเต้นเบา ๆ ป้องกันกดซ้ำและแก้ฟอร์มระหว่างส่ง รองรับ error/retry ร่างยังอยู่เมื่อส่งไม่สำเร็จ ไม่มีการแสดงความสำเร็จในไฟล์ตัวอย่างที่ยังไม่เชื่อมเซิร์ฟเวอร์

อัปเดต 1.7: ภาพคู่บ่าวสาวมีลำดับเผยซุ้ม–คู่บ่าวสาว–ภาพเต็มพร้อมข้อความเชิญ ใช้ Orange Avenue Regular สำหรับอังกฤษและ Outline เฉพาะจุดตกแต่ง ภาษาไทยใช้ Prompt ฟอนต์ฝังไว้ทั้งหมด


## อัปเดต 1.8 — Explore Around Us

เพิ่มเที่ยวรอบสังคมหลังสถานที่จัดงาน แผนที่จำลอง 2.5D พื้นขาว ตัวกรอง 4 สไตล์ + ทั้งหมด ครบ 16 สถานที่/กิจกรรม เส้นทางแนะนำและคู่บ่าวสาวเคลื่อนไหว Desktop มีแผงรายละเอียด มือถือใช้ bottom sheet พร้อมลาก/ซูมแผนที่และปุ่ม Google Maps

ข้อมูลอยู่ใน `js/travel/locations.js` คู่มือและขนาดภาพทั้งหมดอยู่ใน `docs/TRAVEL-GUIDE-TH.md` ภาพแผนที่/ตัวละครที่เว็บโหลดเป็น WebP รวมประมาณ 417 KiB และมี PNG ต้นฉบับสำหรับรีทัช ภาพสถานที่จริงใช้ placeholder ระบุชัดเจน ส่วนระยะทาง/เวลาเดินทางจากบ้านยังเป็น null เพราะไม่ยืนยันพิกัดต้นทาง จึงไม่สร้างค่าประมาณขึ้นเอง

ผ่าน `node --test tools/test-travel.cjs` และการตรวจไฟล์แพ็กเกจ ไม่ได้ทดสอบผ่าน browser/device จริงในรอบนี้


## อัปเดต 1.9 — ปรับส่วนท่องเที่ยวและเติมภาพจริง

ย้าย Travel Guide เป็นส่วนสุดท้ายก่อน footer หลังคำอวยพร ถอดตัวละคร/รถที่เคลื่อนทับแผนที่ออก และเพิ่มภาพจริงของสถานที่พร้อมเครดิตที่เปิดดูต้นทางได้ ภาพ 8 รายการโหลดจากไฟล์ในแพ็กเกจ และอีก 8 รายการเรียกจากต้นทางออนไลน์ มีต้นฉบับของภาพที่ดาวน์โหลดสำเร็จสำหรับรีทัชและรายการแหล่งภาพใน `docs/TRAVEL-PHOTO-CREDITS.md` รายละเอียดการใช้สิทธิ์แต่ละภาพระบุตามแหล่ง ไม่ถือว่าภาพทั้งหมดมีใบอนุญาตแบบเปิด


## อัปเดต 2.0 — หน้าเปิด กำหนดการ และบันทึกคำอวยพร

เพิ่ม mesh gradient เคลื่อนไหวช้าในหน้าเปิด รองรับปุ่มพักภาพ จัดชื่อบนมือถือเป็น Somchai / & / Phantira สามบรรทัด เพิ่มความหนาตัวเลขเวลา เริ่ม 09:09 จบ 12:00 น. สถานที่ระบุ ตำบลนางิ้ว อำเภอสังคม จังหวัดหนองคาย ตามข้อมูลเจ้าของงาน ปุ่มแชร์คำเชิญเป็นปุ่มทึบ

เพิ่มบันทึกคำอวยพรเป็น PNG ด้วยเทมเพลตต้นฉบับที่แนบมา เลือก 4:5 (1080×1350) หรือ 16:9 (1920×1080) ทั้งตัวพิมพ์และลายมือ ไม่ได้แปลงภาพแนวนอนเป็น 9:16 ส่งถึงบ่าวสาวและดาวน์โหลดเป็นคนละคำสั่ง คู่มือ `docs/WISH-EXPORT-TH.md`

ภาพออนไลน์ 8 รายการยังต้องเชื่อมอินเทอร์เน็ตและยังไม่ได้ทดสอบการโหลดบนอุปกรณ์จริงในรอบนี้ แหล่งและเครดิตครบในคู่มือภาพ ไม่ได้อ้างว่าทุกภาพรวมออฟไลน์

## อัปเดต 2.1 — จัดหน้าการ์ดคำอวยพร ปุ่มแชร์ และแก้ป้ายสถานที่

ข้อความคำอวยพรบนภาพ PNG (ทั้งแบบพิมพ์และลายเซ็นชื่อผู้ส่ง) เปลี่ยนจากกึ่งกลางเป็นชิดซ้าย และเริ่มบรรทัดแรกใกล้ขอบบนของกรอบข้อความแทนการจัดกึ่งกลางแนวตั้ง แก้ที่ `js/wish-export.js` เทมเพลตภาพต้นฉบับไม่ถูกแตะต้อง

เพิ่มปุ่ม "แชร์การ์ด" ในหน้าต่างตัวอย่างการ์ดคำอวยพร คู่กับปุ่มดาวน์โหลด PNG เดิม ใช้ Web Share API (`navigator.share` พร้อมไฟล์ภาพ) ซึ่งเป็นระบบของเว็บเบราว์เซอร์ที่เทียบเท่า Native Share Sheet ของแอป (`UIActivityViewController` บน iOS และ `Intent.ACTION_SEND` บน Android) เพราะแพ็กเกจนี้เป็นเว็บไซต์ ไม่ใช่แอปเนทีฟ ปุ่มจะแสดงเฉพาะบนอุปกรณ์/เบราว์เซอร์ที่รองรับการแชร์ไฟล์ภาพจริงเท่านั้น (ส่วนใหญ่คือ Safari/Chrome บนมือถือ) หากไม่รองรับจะซ่อนปุ่มไว้และเหลือปุ่มดาวน์โหลดตามเดิม ไม่มีการจำลองว่าแชร์สำเร็จ

ตัดปุ่ม "คัดลอกที่อยู่" ออกจากส่วนสถานที่ พร้อมโค้ดที่เกี่ยวข้องใน `js/app.js` และเปลี่ยนป้ายชื่อสถานที่จาก "บ้านของเรา" เป็น "สถานที่จัดงาน" ทั้งใน `js/config.js` และ HTML ต้นฉบับ ที่อยู่ `ตำบลนางิ้ว อำเภอสังคม จังหวัดหนองคาย` ยังคงเดิมตามที่ตั้งไว้แล้วในรอบก่อนหน้า

เพิ่ม section ใหม่ "Dress Code" ระหว่างกำหนดการกับส่วนสถานที่ แสดงสวอตช์สี 5 สีโทนสดใสแบบงานบุญอีสาน (ส้มสด ชมพูบานเย็น เหลืองทอง เขียวมรกต ฟ้าสด) ตามที่เจ้าของงานให้เลือกเอง เก็บชื่อสี/รหัสสีไว้ใน `js/config.js` (คีย์ `dressCode`) เป็นแหล่งข้อมูลหลักเหมือนส่วนอื่น แก้สีหรือจำนวนสีภายหลังได้จากไฟล์เดียว ถ้าลบ `colors` ออกจนว่าง ส่วนนี้จะซ่อนอัตโนมัติ

ตรวจไฟล์รอบนี้แล้วแก้เพิ่ม 3 จุด: (1) การจัดข้อความชิดซ้ายรอบแรกเว้นขอบบนหลังคำนวณบรรทัดเสร็จ ทำให้บรรทัดสุดท้ายล้นกรอบข้อความได้สูงสุดราว 7 px เมื่อข้อความยาวเต็มพื้นที่ แก้เป็นหักระยะเว้นขอบออกจากพื้นที่ก่อนจัดบรรทัด ตอนนี้ไม่ล้นทุกขนาดอักษร (2) เพิ่มการตรวจ null ก่อนซ่อน section Dress Code กันหน้าเว็บพังหากลบ section ออกจาก HTML ภายหลัง (3) เปลี่ยนเส้นขอบสวอตช์สีจากขาวโปร่งเป็นวงแหวนเข้มจาง เพราะสีอ่อนอย่างเหลืองทองมีค่าคอนทราสต์กับพื้นขาวเพียง 1.67 ขอบจึงจางหายบนจอสว่าง

ผ่าน `node --test tools/test-wedding-update.cjs` (5/5), `node --test tools/test-travel.cjs` (9/9), `python3 tools/validate.py` และการรันสคริปต์ทั้ง 9 ไฟล์ผ่าน DOM จำลองโดยไม่มี error ยังไม่ได้ทดสอบการกดปุ่มแชร์และหน้าตา Dress Code จริงบนอุปกรณ์ iOS/Android ในรอบนี้

## อัปเดต 2.2 — ตรวจสอบและปรับการปรับตัวตามขนาดหน้าจอ (Responsive)

ไล่ตรวจ breakpoint ทั้งหมดในทุกไฟล์ CSS: `styles.css` มี ≥1450px (จอใหญ่), ≤800px (แท็บเล็ต/จอเล็ก), ≤600px (มือถือ); `travel.css` มี ≤900px และ ≤600px แยกของตัวเอง เพราะแผนที่ต้องการพื้นที่ต่างจากเนื้อหาข้อความ; ทั้งสองจุดตัดครอบคลุมความกว้างแท็บเล็ตจริงที่ตรวจสอบ (iPad 768/820/834, iPad Pro แนวนอน 1024+) ปรับตัวได้ตามที่ควรอยู่แล้วเป็นส่วนใหญ่ ไม่ต้องแก้โครงสร้าง grid ใหม่

พบและแก้ 2 จุด: (1) ปุ่ม "เปิดประตูสู่วันของเรา", "ส่งคำอวยพร" และ "แชร์คำเชิญ" กำหนด `min-width` ตายตัว (255/230/210px) ซึ่งจะดันให้ล้นขอบจอในอุปกรณ์ที่แคบผิดปกติ เช่น จอพับตอนพับ (~260–280px) เปลี่ยนเป็น `min-width:min(Npx,100%)` กันไว้ (2) หน้าเปิดเว็บ (splash) คำนวณตามความกว้างเท่านั้น เมื่อพลิกมือถือเป็นแนวนอน (จอเตี้ยแต่กว้าง เช่น 812×375) เนื้อหาสูงเกินจอจนต้องเลื่อนดูก่อนถึงปุ่มเข้าเว็บ เพิ่ม `@media(max-height:480px) and (orientation:landscape)` ลดระยะเว้นและขนาดโลโก้/ตัวนับถอยหลังเฉพาะกรณีนี้ พร้อมลดความสูงแผนที่ท่องเที่ยวในเงื่อนไขเดียวกัน

ตรวจแล้วไม่พบปัญหา: ปุ่ม/ช่องกรอกทั้งหมด ≥44px ตามเกณฑ์พื้นที่แตะ, input ใช้ font-size 16px กัน iOS auto-zoom, ไม่มีการใช้ `100vw` ที่ทำให้เกิด scrollbar ซ้อน, แผนที่ท่องเที่ยวคำนวณสเกลจากขนาด container จริงผ่าน `ResizeObserver` ไม่ใช่ค่าคงที่ จึงปรับตามการหมุนจอ/ปรับขนาดหน้าต่างได้เอง, และ dialog ทุกตัวใช้ `dvh`/`svh` แทน `vh` คงที่ รองรับแถบเบราว์เซอร์มือถือที่ยืดหด

ผ่าน `node --test tools/test-wedding-update.cjs`, `node --test tools/test-travel.cjs`, `python3 tools/validate.py` และ DOM จำลองอีกครั้งหลังแก้ ยังไม่ได้ทดสอบบนอุปกรณ์จริงหรือ DevTools responsive mode ในรอบนี้ เพราะเครื่องมือที่ใช้ตรวจไม่มีเบราว์เซอร์ให้เปิดดูจริง แนะนำให้ลองหมุนจอและปรับขนาดหน้าต่างเบราว์เซอร์ดูก่อนส่งงานจริง


## อัปเดต 2.2 — ใช้ ZIP แนบล่าสุดเป็นฐาน

คงการปรับ Dress Code และเนื้อหาของไฟล์แนบที่สอง เพิ่มฟอนต์ PKF-Rayrai สำหรับภาพคำอวยพร ข้อความและชื่อชิดซ้าย ส่งออก PNG แนวตั้ง 2400×3000 หรือแนวนอน 3200×1800 พร้อม metadata 300 DPI รายละเอียดล่าสุดใน `docs/WISH-EXPORT-TH.md` ใช้แทนขนาดภาพของบันทึกเวอร์ชันก่อนหน้า

ปรับน้ำหนักอังกฤษด้วย Orange Avenue เดิม โดยเปิด synthetic weight เพราะไฟล์ที่แนบมีเฉพาะ Regular เปลี่ยน & จาก Outline เป็น Regular ที่อ่านชัดขึ้น แอนิเมชันภาพหลักค่อย ๆ เผยซุ้มและคู่บ่าวสาวโดยไม่เลื่อนภาพซ้อน แล้วเคลื่อนไหวต่อเนื่องเบา ๆ วน 18 วินาที การตอบสนอง scroll/pointer คำนวณจากเวลาจริงเพื่อให้สม่ำเสมอในจอหลาย refresh rate รองรับพักภาพและ reduced motion

ยืนยันชื่อสถานที่จัดงานและที่อยู่ ตำบลนางิ้ว อำเภอสังคม จังหวัดหนองคาย ไม่มีปุ่มคัดลอกที่อยู่ ตัดประโยคเช้าวันหนึ่งตามบรีฟออกแล้ว


## อัปเดต 2.3 — ฟอนต์ การ์ดเชิญ และแผนที่

เปลี่ยนฟอนต์ภาพส่งออกเป็น Noto Sans TC ตามไฟล์แนบ ใช้ Prompt เดิมรองรับภาษาไทยเพราะ Noto Sans TC ไม่มีอักษรไทย คง 300 DPI และข้อความชิดซ้าย เพิ่มที่อยู่เต็มในการ์ดเชิญ ปุ่มส่งความยินดีพาไปเขียนคำอวยพรจริง รายชื่อสถานที่ใต้แผนที่เป็น Dropdown ที่เปลี่ยนตามโหมดและเปิดรายละเอียดได้ทั้งมือถือ/เดสก์ท็อป พื้นที่ว่างในแผนที่เป็นสนามหญ้าเตี้ย UI รอบแผนที่ยังสีขาว
